## 10. 当前迭代发现的问题（待复测）

| 编号 | 问题 | 影响 | 状态 | 备注 |
|---|---|---|---|---|
| P1 | 前端 dev server（开发服务器）存在 5173 端口占用问题 | 一键启动可能失败或改到别的端口，用户体验不稳定 | 已复测 | `npm run dev` 已使用 `--strictPort`，`start.bat` 会清理 5173 / 8000 |
| P2 | 启动/停止脚本对旧进程和 Git Bash（命令行）兼容不够强 | 双击启动可能碰到历史残留进程；从 Git Bash（命令行）执行 `.bat` 可能误用 Git 自带命令 | 已修复并复测 | `start.bat` / `stop.bat` 均清理 5173 / 8000；脚本已显式调用 Windows（视窗系统）系统命令，`stop.bat` 在 Git Bash（命令行）下复测通过 |
| P3 | 恢复默认设置需要保留 API 配置 | 用户测试后不希望每次重新填 key（密钥） | 已修复并复测 | `reset_defaults` 不再清空 `LANGDRILL_PROVIDER_API_KEY`，新增回归测试 |
| P4 | `start.bat` 明文写入 API Key（接口密钥） | 违反环境变量账本规则，也可能覆盖用户自己的配置 | 已修复并复测 | 启动脚本现在只写 MiMo（米魔）默认 provider/model/base_url（供应商/模型/基础网址），不写入 key（密钥） |
| P5 | 写入 `.env` 后当前进程仍可能保留旧 provider（供应商）环境变量 | 恢复默认接口短期返回旧配置，影响设置页判断 | 已修复并复测 | `_write_env` 现在同步当前进程环境变量 |
| P6 | mock（本地模拟）配置会继承真实 Base URL/API Key（基础网址/接口密钥）状态 | 冒烟测试和设置页可能显示误导性配置 | 已修复并复测 | mock（本地模拟）现在隔离 base_url/key（基础网址/密钥），且 `current_with_secret` 不携带真实 key（密钥） |
