# 架构说明

## 核心原则

数据库是唯一正式学习状态来源；聊天上下文只用于交互，不作为事实来源。CLI 与 Web 共享同一个后端核心，不维护两套业务逻辑。模型调用记录 prompt_modules、模型名、token 用量、耗时和校验状态。

## Agent 划分

- Agent 1：`OrchestratorAgent`，识别任务、读取状态、选择 prompt 模块、协调题目和判题流程。
- Agent 2：`QuestionAuthorAgent`，生成结构化题目，经 `QuestionValidator` 校验后入库。
- Agent 3：`EvaluatorTutorAgent`，判题、讲解、错因归因和掌握度回写。

## Prompt Engine

`PromptRegistry` 维护 prompt_modules；`PromptAssembler` 只注入当前任务必要模块。安全规则始终注入；人格提示词只在聊天总结类任务启用；用户全局提示词低优先级，默认不参与正式出题。

## Context Pack

模型调用只携带目标、考试、会话状态、当前题目、相关考纲摘要、最近错误摘要和输出格式。完整学习历史、完整考纲和完整真题不直接进入 prompt。

## Generation Job

数据库已有 `generation_jobs` 状态表：`pending`、`generating`、`validating`、`persisted`、`failed`、`cancelled`。V1 先生成首题并入库，V2 可扩展后台分块生成。

## 复习算法

`mastery_score V1` 综合正确率、最近一次作答、间隔时间、题型难度、提示后答对、综合题表现和错题重复次数。后续可接入 FSRS（Free Spaced Repetition Scheduler，免费间隔重复调度器）作为可选调度器。
