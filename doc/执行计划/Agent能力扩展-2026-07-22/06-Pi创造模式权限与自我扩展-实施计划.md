# Pi 创造模式、权限与自我扩展 Implementation Plan

状态：活动计划；实施暂停。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改变普通学习流程的前提下，把创造模式实现为全局能力覆盖层：可调用受审计的 Pi 文件与命令行工具、安装扩展、执行通用任务和安全地升级项目功能。

**Architecture:** Python `AgentRuntimeGateway` 负责路由与运行生命周期，长驻 Node/Pi RPC sidecar 负责通用 Agent 循环，`ToolPolicyGateway` 在每次工具执行前统一解析权限档位、路径、网络与不可覆盖的灾难性硬限制。Pi 使用请求级内存会话，SQLite 保存正式 Run/Trace；供应商和模型配置复用现有配置，不另建凭据账本。

**Tech Stack:** Python 3.11、FastAPI、SQLite、Node.js 22、TypeScript、`@mariozechner/pi-coding-agent`、React、Tauri 2、PowerShell、Git。

## Global Constraints

- 创造模式是全局设置；开启后所有会话都可获得通用能力，但学习意图仍走现有 TaskRouter 和领域 Agent。
- Pi 不成为学习数据库的事实源，不直接持久化独立聊天树。
- `请求批准`、`智能审批`、`完全访问`、`自定义` 四档共享同一策略引擎；完全访问只保留不可覆盖的灾难性硬限制。
- 不可覆盖的硬限制仅覆盖：未限定根目录递归毁坏、磁盘/分区/引导/固件破坏、隐蔽凭据外传、绕过或关闭本次策略与审计、目标未解析的破坏性操作。
- 正常文件编辑、命令执行、联网和依赖安装不因“看起来像编程”而额外禁止；是否审批由档位和自定义规则决定。
- 复杂编程任务必须加载随应用捆绑的 Superpowers；普通学习任务不注入编程工作流提示词。
- Pi 运行时未就绪时禁止开启创造模式，设置页必须展示原因、安装方案和一键修复。
