# 模型管理与原生思考等级 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把模型设置改成供应商、模型和 reasoning（思考/推理）档位配置驱动，不再用提示词模拟思考等级。

**Architecture:** 后端 `ModelConfigService` 负责供应商、模型、API format（接口格式）和 reasoning 档位元数据；`ModelProvider` 只根据当前配置组装原生 API（接口）请求体。前端只展示后端返回的可用供应商、模型和档位，快捷栏隐藏未配置 API Key（接口密钥）的供应商。

**Tech Stack:** Python（编程语言）+ FastAPI（Web API 框架）+ SQLite（轻量数据库）+ React（前端框架）+ TypeScript（类型化 JavaScript）+ Vite（前端构建工具）。

---

## 文件结构

- 修改 `backend/langdrill_agent/services.py`：内置供应商四个：OpenAI/GPT、Claude、DeepSeek、MiMo；加入模型级 reasoning profile（推理档位配置）、供应商启用状态、API Key（接口密钥）状态、自定义供应商持久化。
- 修改 `backend/langdrill_agent/providers.py`：删除 `_thinking_instruction`；根据 `api_format` 和 `reasoning_parameter` 写入原生参数；新增 Anthropic Messages（Anthropic 消息接口）请求。
- 修改 `backend/langdrill_agent/models.py`：`ModelConfigRequest.thinking_level` 从固定 Literal（字面量类型）改为普通字符串，允许模型自定义档位。
- 修改 `backend/langdrill_agent/api.py`：创建 `ModelProvider` 时传入 API format（接口格式）与 reasoning 参数信息。
- 修改 `frontend/src/types.ts`：供应商、模型和思考等级类型从字符串数组升级为配置对象，允许自定义档位。
- 修改 `frontend/src/App.tsx`：模型下拉跟随供应商；思考等级下拉跟随模型；设置里提供“添加思考等级”；快捷栏只显示 enabled（已启用）且 has_api_key（已配置密钥）的供应商。
- 新增/修改 `try/test_model_config.py` 与 `try/test_provider_reasoning.py`：先写失败测试，再实现。
- 更新 `AGENTS.md`、`doc/验收标准.md`、当天进展记录。
